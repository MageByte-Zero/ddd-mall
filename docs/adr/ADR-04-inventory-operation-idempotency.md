# ADR-04：库存动作同时保留业务预占与请求结果

- 状态：本地实现，待整篇交付审阅；2026-10-08
- 约束：承接 L12 三字段；成功提交可能丢响应；同SKU有独立订单；跨BC仍使用Seata AT。

## 决策

reservationNo保护业务归属与整笔生命周期，requestKey保护重放结果和参数；两个身份分别有唯一约束，同预占单+动作也唯一。先SKU当前锁定读，再回执当前锁定读；@GlobalLock + @Transactional 防另一事务提前把一阶段结果读成成功。库存、预占状态、回执、日志同一本地事务。领域预占实体、结果 record 与端口不依赖外层，SQL/Seata由外层落实。

本讲为可解释的事务边界串行同SKU，普通业务成功路径走锁内聚合保存，并不主张高吞吐最优。没有失败窗口时不提前插一条独立已完成回执，也不把独立Redis锁作为真实结果来源。requestKey无TTL自动清理，生产需要业务保留策略。

## 备选

仅存 requestKey：换key仍可重复释放，缺少归属；仅保生命周期：无法返回首次结果，也无法核对跨动作同key误用；Redis SETNX后写MySQL：两套系统非同一本地事务，失败窗口需补协调；保留L12原子库存写+独立预占行锁：可以扩展，但需真实流水快照/AT全局锁/锁顺序设计，本讲不未经验证宣称更快。

## 代码证据

`IdempotentInventoryService.execute`、`Reservation.finish`、`InventoryOperationMapper`、V3迁移、`InventoryIdempotencyTest`、库存`ArchitectureTest`。Seata窗口证据以文章evidence实际运行结果为准，注解存在不构成证明。

## 可逆性

接口适配器与持久化端口可替换，业务身份/生命周期契约仍保留。已经产生新预占单后，不能把流量直接切回L12匿名释放，也不能删除回执表恢复旧接口。历史无归属余额需对账；V3不编造历史单号。若回退部署，先停止新协议写入并制定数据保留/迁移方案，不回滚数据解释。
