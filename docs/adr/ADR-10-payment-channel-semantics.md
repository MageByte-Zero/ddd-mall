# ADR-10 在支付边界翻译渠道语义

状态为已确认的教学政策。V2 为同一个模拟渠道的另一份协议。

## 场景与选择

V1 的 SUCCESS 提供确定收款的结果。V2 用 SUCCESS 报告受理，渠道此时可以给出受理编号。V2 的 CAPTURED 才报告已经收款并提供收款流水。把同名状态或两个外部编号直接转成同一事实，会让已受理的订单提前进入已付款流程。

支付边界选择协议、核验来源、精确转换金额，并解释报文提供的证据。回调与查单共享 V2 翻译。查询超时只表示当前没有观察结果。查单使用原支付单的引用，调用发生在确认事务之前。

在单一且语义稳定的渠道中可以直接在入口做少量转换。采用 V2 后，直接传递外部模型会使应用或领域代码承担协议差异。单独的字段映射可以吸收改名和单位变化，但还需一条明确的语义规则才能区分受理、收款和未知。当前在 mall-payment 内实现这个边界，部署仍由现有服务负责。

## 时间边界与退出条件

聚合检查归属、金额、币种和流水。确认用原有支付行锁和本地事务，支付事实与 Outbox 同时提交，订单按 ADR-08 独立决定是否接受。请求拒绝留下核查原因，支付单仍以 PENDING 和 SUCCEEDED 表示确认进度。

V1 和 V2 走各自凭据与路径，二者共用原支付和渠道流水身份。启用 V2 后保留在途结果的处理入口。单纯字段或单位演进可在该边界适配。如果业务接受预授权、部分收款或多次付款，需要重审支付证据、尝试身份和订单接受条件。
