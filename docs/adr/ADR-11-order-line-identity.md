# ADR-11：订单行身份与库存预占

- 状态：已接受，教学政策于 2026-11-22 确认
- 关联：[订单行需求](../../fixtures/requirements/order-lines.md)、[事件契约](../../fixtures/contracts/order-events.yaml)

同一 SKU 可在整单内承接两张独立的采购申请。业务需要从成交行核对原预占与出库记录。库存总量仍以 SKU 为单位，支付和发货仍以订单为单位。

## 决策

订单分配 `lineId`，与成交快照一起持久化。新库存引用为 `orderNo:LINE:lineId`，从创建到取消和发货都复用。订单根管理各行和整单金额、状态。库存管理 SKU 容量、预占终态及其动作回执。

继续使用 Seata AT 保证整单建单与取消；库存消费在一笔库存本地事务里提交两行和 Inbox。事件版本以及行与预占的关联在接收边界校验。发货本地完成与库存最终出库是两个完成点。

合并成交行适合只关心 SKU 总量的需求。展示序号仅供排序。保留成交明细再把库存合计成一笔，适合由订单维护分配且库存侧只核对合计的契约。本例要求库存动作逐行可追踪，直接保留对应预占。

## 存量与退出

Flyway V4 用既有主键生成旧行身份；已有库存号、动作回执和 Outbox 保留原样。历史履约只有在唯一候选及库存原单能够核对时继续；歧义或缺失的预占留待核查。v2 沿原指纹与已有 Inbox 去重。v3 消费端就绪后再启用新写入。暂停新建多行后，继续让兼容版本读取已建订单、处理在途事实。V4 约束要求停止旧订单写入后迁移，完整混跑切换在后续讲次讨论。
