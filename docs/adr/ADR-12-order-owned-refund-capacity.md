# ADR-12 由订单聚合守住部分退款额度

## 决策

`Order` 统一判断每行数量、整单金额和退款模式。部分退款用有独立身份及结果的订单内实体表达。订单聚合写入根版本、退款记录和既有履约事实时共用订单库事务。申请与结果处理遇版本冲突可在新事务最多尝试三次，重新执行领域规则。未知结果持续占用，只有可信最终拒绝才能释放。

## 权衡

单张退款单适合管理独立审批，自己的记录却只覆盖一笔申请，仍需有权批准每笔占用的共同所有者。单独的退款额度聚合可以从订单履约写入中分离，但需要建立可信的成交与实付额度，并协调原整单入口。当前业务每次基于同一订单决定额度、模式与申请，沿用该聚合和已有乐观锁。代价是同订单写入会争用同一版本，历史增长会提高聚合读取成本。出现独立团队、长期审批或实测竞争成本时再评审拆分。

## 兼容与退出

增量迁移只新增子表，继续读取旧整单状态、退款列和原有事件，不给存量推断部分退款记录。暂停新申请时保留读取和回记能力，处理存量在途申请后再评估切换。新增退款记录属于业务事实，切换应用版本不能撤销这些事实。

课内结果由受控测试适配器提供。退款发起、真实资金渠道、过程恢复与跨上下文发布依赖后续协作设计。
