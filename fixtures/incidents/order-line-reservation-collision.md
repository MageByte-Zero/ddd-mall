# 同 SKU 的两条明细用了同一个预占号

教学反例，基线为 `lesson-19`。在订单聚合构造两条相同 SKU 的行，数量分别为 1 和 2，单价均为 50.00。整单支付 150.00 后调用发货。旧聚合拒绝重复 SKU，订单保持 PAID，发货事件新增 0 条。库存 v2 模型接收同一个 `orderNo:SKU` 的两项明细，也会拒绝重复预占号。

旧做法保护了单 SKU 一笔预占的政策。若仅移除发货守卫，两个合法动作仍会碰到同一 `reservationNo`，在库存回执里出现同身份异参的冲突。若按 SKU 合计保存一条订单明细，又会丢失两张采购申请与原预占的对应关系。

验证新模型时，应同时保留合法两行、拒绝同身份异参。已有数据找不到原预占时停止履约，保留订单号与候选预占号供核查。
