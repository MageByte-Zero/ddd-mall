# 第 16 讲一致性场景

本文件用教学场景说明 `lesson-15` 已有行为和可比较的设计。创建与取消范围见 [订单需求](order-creation.md)，退款政策见 [整单退款需求](full-refund.md)。

假设一种商品总量 10 件，单价 50 元。订单 O 购买两件，预占单 R 记录这两件归属。库存快照依次为总量、可售、已预占。以下是同一案例的不同分支及预期，使用独立输入观察各分支。

| 动作 | 完成条件 | 可观察的中间态 | 确认与恢复责任 |
|---|---|---|---|
| 创建 | O 为 `PENDING_PAY`，R 为 `RESERVED`，库存 `10 / 8 / 2` | 参与分支的一阶段本地提交可见，全局结果仍未决 | 订单用例协调库存。结合全局事务标识、订单号和预占身份判断结果 |
| 未支付取消 | O 为 `CANCELLED`，R 为 `RELEASED`，库存 `10 / 10 / 0` | 释放分支已本地提交，仍可能被全局回滚 | 订单用例协调释放，按原预占与释放动作核对结果。异常时检查协调状态和实际数据 |
| 发货登记 | O 为 `SHIPPED`，状态历史和含原预占明细的发货事实共同留存 | 库存仍是 `10 / 8 / 2`，确认出库后为 `8 / 8 / 0` | 订单负责事实投递，库存订阅负责按原预占确认。用事件身份和出库动作身份分别核对进度 |
| 退款申请 | 订单保存申请身份、金额与申请前状态 | `REFUND_REQUESTED` 可记录结果未知或拒绝 | 订单负责申请与记账，未来支付边界负责按原资金动作确认结果 |
| 退款完成 | 订单接受身份与金额均匹配的确定成功结果 | 未发货库存可依政策另行释放，已发货的事实继续成立 | 现有测试以模拟结果确认订单侧记账。库存及退货验收由对应责任方单独处理 |

可用下列输入检查决策，历史运行和教学推演的出处见本讲文章的核验索引。

| 输入 | 应观察到的业务结果 |
|---|---|
| 仅剩两件，两个独立订单各申请两件 | 总新增预占至多两件，合法请求依据剩余容量判断 |
| A 已释放后重放同一动作，B 另有三件预占 | A 无新增副作用，B 保留三件且后续合法释放可执行 |
| 库存分支一阶段已提交，全局仍未决 | 受保护的独立重放不能提前确认成功。回滚结束后，写入和回执按实际结果核对 |
| 订单待发送行处于全局未决窗口 | 受保护中继等待全局结果。回滚后行消失，提交对照组可以继续发送 |
| 发货事实已留存，消费延迟或提交后重投 | 预占仍排除在可售余额之外。同一预占最终只确认一次，合法的另一笔动作仍可处理 |
| 两个同版本的订单分别尝试发货和申请退款 | 只一方提交，新增的发货或申请事实合计一条。后续操作重新读取并判断 |
| 同一退款申请收到未知、拒绝及匹配成功结果 | 前两种保持申请中。匹配的确定成功产生一次完成事实，重放不增加，保留原履约来源 |

如果创建改为先受理再确认，受理回执必须能关联同一请求，且允许查询未确认进度。库存按原业务身份原子预占，订单只在收到有效预占确认后宣布完成。确认失败或未知要有恢复责任和终止条件。这个方案用于比较现有承诺和替代承诺，具体等待时限与恢复政策由采用方定义。
