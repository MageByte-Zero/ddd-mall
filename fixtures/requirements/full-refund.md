# 整单退款教学需求（第15讲）

来源：虚构教学案例。政策于2026-10-21经作者确认，不代表所有电商规则。

## 业务语言与规则

- 取消：未付款关闭订单；退款：退回已付款项；退货：货物逆向流转；重新可售：库存根据验收决定。四者不可互换。
- 只整单退实付，支持PAID和SHIPPED申请，PENDING_PAY/CANCELLED/RECEIVED拒绝。
- 一个订单只有一笔有效整单申请；refundNo是稳定申请身份，重放复用。申请金额与实付相等，原因非空且不超过200字。refundNo最多64字符，在订单库全局唯一。
- 同申请同金额同原因重放不新增历史/事件；同申请异参拒绝；换申请号不能绕过已有整单申请。
- 申请前状态固定保留（PAID或SHIPPED）；申请后不再新增发货。发货已经提交时不撤销发货事实，即使库存消息还未消费。
- 结果携带refundNo、amount、outcome、reference。outcome为UNKNOWN/REJECTED/SUCCEEDED；SUCCEEDED要求非空结果凭证。拒绝和未知不记REFUNDED，不自动创建新申请。
- 确定成功且身份/金额匹配，才REFUND_REQUESTED→REFUNDED。相同成功凭证重放不新增事实；成功后不同凭证或降级结果拒绝。结果可信来源鉴别不在本讲模拟范围。
- PAID退款可安排释放其预占，但退款完成和释放完成分别确认；SHIPPED退款不自动release或restock。晚到OrderShipped仍按原事实确认出库，不查询当前退款状态改写事实。

## 最小模型范围

Order聚合内管理Refund实体，Refund无独立仓储；Money与RefundResult为值对象。申请与完成各产生一次RefundRequested/RefundCompleted事实。应用服务仅编排订单本地事务，结果通过可控测试模拟输入。没有真实渠道、生产退款HTTP入口、自动退款发起、自动库存释放、持久化重试、退货或部分退款。

## 验收场景（预期独立于实现）

| 输入 | 预期 |
|---|---|
| 未付款申请100元 | 拒绝，原状态和事件不变 |
| 已付款100元申请100元 | 申请中，一条申请事实，来源PAID |
| 已发货100元申请100元 | 申请中，来源SHIPPED，无库存释放/补货动作 |
| 同身份同参重放 | 仍一条申请事实 |
| 同身份改金额/原因，或另申请号 | 拒绝，不修改原申请 |
| 金额99元整单申请 | 拒绝 |
| 未知或明确拒绝的结果 | 仍申请中，记录结果 |
| 错身份/错金额成功 | 拒绝 |
| 合法成功结果 | 已退款，一条完成事实 |
| 同成功凭证重放 | 不再产生完成事实 |
| 成功后未知/不同凭证 | 拒绝，不倒退 |
| 申请后发货 | 拒绝 |
| 同版本发货与退款竞争保存 | 只一方成功，失败事务无幽灵事件 |
| 保存重读 | 申请身份/金额/来源/结果保留，不产生新事件 |

失败样例见fixtures/incidents/refund-is-not-inverse-order.md。测试不能证明真实资金返还、渠道幂等或跨服务恢复，后续第17/24讲深化。
