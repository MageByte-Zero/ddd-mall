# 第 17 讲支付确认与订单交接

## 教学政策

- 一个订单固定一张支付单，全额 CNY，模拟渠道按整数分通知。支付单源自已提交且仍允许支付的订单快照，创建重试复用原支付单。已确认的支付单保持成功，未知结果按原身份继续核查。
- 支付确认与应交接事实一起提交，订单可以暂未接受付款。若订单取消全局提交在先，订单保留取消，支付保留收款，通过处理回执把该笔资金交支付运营核查。
- 存量订单保留既有教学路径。开启新订单支付路径后，新订单才能创建支付单，旧入口不可直接更改它们。关闭开关只影响之后创建的订单。
- 只对受控模拟连接开放回调。来源需通过独立教学凭据校验，管理接口和事件交接使用另一份教学密钥。

## 可核对输入

每条订单独立创建，两件商品每件 50.00 元，库存示例起点总量 10、可售 10、预占 0。付款 10000 分，渠道流水在同一模拟渠道内唯一。

| 分支 | 可观察到的最小结果 |
|---|---|
| 首次成功与重放 | 只确认一张支付单、一个支付 Outbox 事实，订单只发生一次 PAID 迁移，库存继续预占两件 |
| 原事件重投和同支付换事件号 | 事实指纹相同可重投；原事件异参或原支付异参拒绝。独立订单仍可付款 |
| 结果异常 | 未知没有推进权限；错单、错金额、错币种、冲突流水、未识别结果留下核查记录 |
| 迟到收款 | P 已确认，O 已取消，库存已释放；可按 P 查到 REVIEW_CANCELLED_ORDER |
| 一阶段可见 | 未决创建不可发起支付；未决取消不可确认拒绝。提交或回滚后重新读取 |
| 交接故障 | 未提交的支付确认没有事件；待交接行可在进程恢复后发送；消息重复不重复推进订单 |
| 存量迁移 | 历史状态、金额、退款与事件可读，旧路径与新路径隔离，停止开通不影响在途 |
